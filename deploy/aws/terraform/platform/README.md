# Stateful AWS platform

One private EC2 host runs the existing CTFd/MariaDB/Redis Compose definition
behind an internal HTTPS ALB. A separate encrypted gp3 volume holds the database,
uploads, CTFd logs, and Redis data. No managed database, public IP, or SSH ingress.

This is a separate Terraform state from `foundation/`. It is **not** disposable
team infrastructure. The configuration and local recovery test are verified;
AMI boot, live AWS permissions, and an actual EBS restore still require rehearsal.

## Prerequisites

- The [foundation](../README.md), with its VPC, subnets, endpoint-client group,
  and ECR repositories. Use those outputs in `event.tfvars`.
- An issued ACM certificate in this account/region and a private DNS hostname
  covered by it. Create an alias to the ALB outputs after deployment; using the
  raw ALB hostname will not match your certificate.
- Company `ssm` and `ssmmessages` endpoints with private DNS. Their security
  groups must allow TCP 443 from `host_security_group_id`. Foundation endpoint
  policies must allow platform ECR pulls and secret reads. We do not modify
  company endpoint ingress or policies.
- A trusted, clean x86_64 Nitro-compatible AMI with cloud-init, systemd, Bash,
  Docker Engine, the Compose plugin, AWS CLI v2, and SSM Agent 3.3.40.0 or newer.
  Standard Linux tools include `wipefs`, `blkid`, `mkfs.ext4`, `mountpoint`, `sync`,
  and `flock`. Its udev rules must expose EBS disks as
  `/dev/disk/by-id/nvme-Amazon_Elastic_Block_Store_vol<id-without-hyphen>`.
  No package downloads occur at boot. The AMI must not contain running workloads,
  credentials, or event data. Compose 5.5.1 is locally tested.
- The three platform images from the root `compose.yaml`, mirrored to foundation
  ECR repositories and supplied as immutable digest URIs. Publishing automation
  remains a later stage; this root does not build or push images.
- An existing Secrets Manager secret containing only the two platform runtime
  values described below. Terraform accepts its ARN, never its contents.
- If using a company EBS KMS key (including a customer-managed account default),
  set `ebs_kms_key_arn`. Its key policy must allow the deployment identity and
  `backup_role_arn` to use it. Terraform adds scoped backup-role permissions but
  does not edit company key policies. Retain the key with the snapshots. See
  [AWS encryption permissions](https://docs.aws.amazon.com/ebs/latest/userguide/dlm-prerequisites.html).

## Platform secret

From the repository root, after `mise run env:init`, export only the database
password and signing key. Do not copy the full event `.env` to EC2:

```bash
umask 077
mise exec -- python3 -c 'import os; print("\n".join(k + "=" + os.environ[k] for k in ("CTFD_DB_PASSWORD", "CTFD_SECRET_KEY")))' > platform.secret.env
aws secretsmanager create-secret --name devops-ctf/platform \
  --secret-string file://platform.secret.env --query ARN --output text
```

`platform.secret.env` is gitignored and sensitive. Both values must be 64-character
lowercase hex strings, as generated by this repository. Supply the returned ARN
and, if using a customer-managed secret key, `secret_kms_key_arn`.

Older checkouts generated a 32-character database password. `env:init` preserves
existing values, so pulling this fix does not migrate an existing `.env`. For a
new AWS event, generate a fresh event configuration in a separate checkout.
Do not change an initialized database's password by editing `.env` or rotating
the secret alone; existing events require a coordinated database migration.

The host pins the first secret version on the data disk. Restarts and restored
snapshots reuse that version, not a newly rotated database password. Preserve
the secret and its version for the lifetime of all retained snapshots. Do not
rotate it mid-event without a coordinated database migration. Admin credentials
stay on the operator workstation and are used through CTFd's setup workflow.

## Deploy and release

```bash
cd deploy/aws/terraform/platform
cp backend.hcl.example backend.hcl
cp event.tfvars.example event.tfvars
# Edit both files and authenticate using your company AWS profile.
terraform init -backend-config=backend.hcl
terraform plan -var-file=event.tfvars -out=platform.tfplan
terraform apply platform.tfplan
terraform output
```

Use a unique state key such as `self-ctf/<event>/platform-primary.tfstate`.
`enable_player_access` defaults to false: only `admin_ipv4_cidrs` can reach HTTPS
until setup is complete. Those CIDRs must actually exclude players.

Connect through SSM and check `cloud-init status --wait`,
`systemctl status self-ctf.service`, and `journalctl -u self-ctf.service`.
Docker and CTFd both depend on the data mount; a missing disk must stop startup,
not silently create an empty scoreboard. An existing filesystem is never
reformatted. Snapshot restores require the expected ext4 label.

Create the certificate-covered DNS alias and set the workstation's `.env`
`CTFD_URL` to its HTTPS URL. From the repository root, use the existing
`mise run bootstrap`, build/render, and `mise run sync` workflow to initialize
team mode, self-registration, and challenges. Do not run `mise run ci` against a
live platform. Then set `enable_player_access = true` and review/apply the plan.

The ALB forwards only to CTFd port 8000. Database/cache ports remain private to
Compose. IMDSv2 with hop limit 1 keeps host-role credentials out of bridge-network
containers. The instance role uses the standard SSM core policy plus read-only
access to the supplied ECR repositories and platform secret; no challenge flags
or CTFd admin credential enter user data or Terraform state.

## Backups and recovery

Hourly DLM backups stop all three services, verify clean container exits, flush
the data filesystem, request a data-only snapshot, and resume the matching
backup execution. The snapshot transfer can finish after service resumes.
The root disk is excluded. Default retention is 168 snapshots, configurable.
See [AWS's pre/post flow](https://docs.aws.amazon.com/ebs/latest/userguide/script-flow.html).

A failed pre-script does not fall back to a crash-consistent snapshot. A failed
post-script can leave CTFd stopped: inspect its SSM command and systemd journal,
resolve the error, and rerun the post-script with the original execution ID.
The execution marker is `/run/self-ctf-backup`. Do not manually start or replace
the platform while a backup is in flight.

CloudWatch alarms cover prolonged ALB target failure, pre/post script failures,
and snapshot creation/deletion failures. Set `alarm_sns_topic_arn` to an existing
subscribed topic for notifications; without it, alarms are console-only. Check
backup freshness as well as errors, especially after disabling a policy.

To rehearse a restore without touching the original:

1. Select a **completed, encrypted** data snapshot for this event. Check its DLM
   pre/post success tags; Terraform requires a successful pre-script tag. Retain
   the original platform and DNS throughout.
2. Copy the example configuration into `recovery.tfvars`, set
   `platform_name = "recovery"`, `restore_snapshot_id`, an adequate disk size,
   `enable_player_access = false`, and `backup_enabled = false`.
3. Use `backend-recovery.hcl` with a **new** state key and a separate cache:

   ```bash
   export TF_DATA_DIR="$PWD/.terraform-recovery"
   terraform init -reconfigure -backend-config=backend-recovery.hcl
   terraform plan -var-file=recovery.tfvars -out=recovery.tfplan
   terraform apply recovery.tfplan
   ```

4. Use a certificate-covered recovery hostname to verify accounts, team scores,
   solves, uploads, and the pinned secret version. Change the event DNS only
   after validation. Enable backups on the recovered platform before release.

EBS volumes are AZ-bound, but a snapshot can create a new disk in another AZ in
the region. This is manual recovery, not high availability. The single host can
be unavailable between a failure and recovery, and failed/missing backups can
make the recovery point older than an hour.

## Changes and teardown

The data volume has Terraform `prevent_destroy`. Changing its snapshot or AZ
in place is deliberately blocked. Host/ALB deletion protection is also on:
disable `protect_instance` in a separate reviewed apply before intentionally
replacing a host. User-data/image changes replace the host, not the data disk.

Never reset a team by destroying this root. Final data deletion requires an
explicit review and removal of the lifecycle guard. Snapshots, the secret,
foundation, and state bucket have separate lifecycles; retain them until the
event's recovery requirements are finished.

## Tests

From the repository root: `mise run check`, `mise run terraform:check`,
`mise run platform:check`, and `mise run platform:test`.

The last command uses new local stacks with throwaway credentials to verify the
AWS Compose overlay, secure cookies, clean shutdown, and recovery of database
and upload fixtures into fresh containers. It stops its containers but retains
its fixture data/volumes. It does not modify the existing local CTF or contact AWS.
